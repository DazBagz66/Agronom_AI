# Agronom AI

Локальное приложение: обследования растений, фотографии, текстовые дополнения,
сохраняемые сессии и рекомендации на русском языке.

## Запуск

Windows, Python 3.12. После подготовки достаточно открыть `start.bat`.

```powershell
python -m pip install -r requirements.txt
npm.cmd ci --prefix react-frontend
npm.cmd run build --prefix react-frontend
python -m uvicorn main:app --app-dir backend --reload
```

Откройте http://127.0.0.1:8000. После изменения интерфейса повторите сборку.
Для обучения отдельно нужны зависимости из `requirements-training.txt`.

## Текущее состояние

- Сессии с фотографиями, текстовыми уточнениями и исправлениями пользователя.
- Автоматическое определение объекта кукурузы на MobileNetV3 Large: лист,
  початок, общий вид и прочие объекты. Ручной переключатель не нужен.
- Подсолнечник: дообученная MobileNetV3 Large, четыре класса (ложная мучнистая
  роса, серая гниль, повреждения листьев, здоровый лист). Точность на
  отложенном тесте 92,5 %; единственная путаница — часть повреждений листьев
  принимается за ложную мучнистую росу.
- Кукуруза, листья: включена `corn_candidates/leaf_v3` (MobileNetV3 Large,
  обучена на снимках из нескольких источников, чекпойнт 8-й эпохи). Выпущены
  три класса: обыкновенная ржавчина, серая пятнистость, здоровый лист. На
  источниках, не участвовавших в обучении, здоровые листья распознаются
  почти всегда (Ecuador 138/138, IDADP 100/100), ржавчина — в 81 % случаев.
  Гельминтоспориозы и курвуляриоз остались в модели, но не выпущены: на чужих
  источниках они почти не распознаются (южный гельминтоспориоз чаще всего
  принимается за ржавчину), их вероятность показывается как «нельзя
  подтвердить причину». Нужны примеры этих болезней из разных источников.
- Кукуруза, початки: включена `corn_candidates/ear_v3` (MobileNetV3 Large,
  три класса: пузырчатая головня, гниль початка без уточнения вида, початок без
  видимых признаков болезни). Данные: iNaturalist (головня, здоровые), IDADP и
  HF ricemaize (гниль), 117 отобранных вручную фотографий здоровых початков с
  Wikimedia Commons (`backend/scripts/acquire_wikimedia_ears.py`,
  `review_wikimedia_ears.py`). Отложенный тест: 95 % точности, все три класса
  с precision и recall выше 0,88; тест по гнили не независимый (оба источника
  участвуют в обучении). Вид гнили модель не различает.
- Уверенный класс «здоровый» у листа и початка показывается зелёным статусом
  с оговоркой; старые записи прежних моделей остаются наблюдением.
- Орган кукурузы определяется автоматически; при сомнении определитель
  спрашивает модель листьев и принимает её уверенный ответ.
- Разбор текста и 10 карточек кукурузы с русскоязычными инструкциями.

Прежние классификаторы на замороженном MobileNetV2 удалены по запросу
пользователя: на внешних полевых фотографиях кукурузы они давали около 33 %
точности и называли здоровые листья больными. Сохранённые результаты
относятся к прежним обследованиям; фото не пересчитываются.

## Модели: обучение и включение

Все классификаторы болезней обучаются одним скриптом и подключаются через
реестр `backend/data/models/registry.json` (`{культура: {орган: каталог}}`).
Сервер запускает только модели из реестра со статусом `approved` и совпавшей
контрольной суммой; иначе честно отвечает, что модели нет.

```powershell
# Подсолнечник: папки-классы, разбиение по группам похожих снимков.
python backend/scripts/train_classifier.py --crop sunflower --folder ".cache/datasets/sunflower/images/Original Image" --splits-from backend/data/models/sunflower/training_report.json --output backend/data/models/sunflower_candidates/leaf_next
# Кукуруза: защищённые манифесты corn_field.
python backend/scripts/train_classifier.py --crop corn --manifests .cache/datasets/corn_field/manifests --organ leaf --output backend/data/models/corn_candidates/leaf_next
# Прерванный запуск: оценить и экспортировать сохранённый лучший чекпойнт без переобучения.
python backend/scripts/train_classifier.py --crop corn --manifests .cache/datasets/corn_field/manifests --organ leaf --output backend/data/models/corn_candidates/leaf_v3 --evaluate-only
# Включение: по умолчанию выпускаются классы, прошедшие правило из манифеста
# (>=15 тестовых примеров, precision и recall >=0.70); --classes задаёт список вручную.
python backend/scripts/activate_model.py backend/data/models/sunflower_candidates/leaf_next
```

Каждый каталог модели содержит `model.onnx`, `manifest.json`,
`training_report.json` (метрики по источникам, все предсказания теста) и копии
разбиений. Подготовка фото для обучения и сервера общая:
`backend/app/diagnostics/preprocess.py`. После включения перезапустите сервер.

## Структура

| Путь | Назначение |
| --- | --- |
| `backend/main.py` | API и сохранение обследований |
| `backend/app/diagnostics/crop_model.py` | Загрузка и запуск классификаторов из реестра |
| `backend/app/diagnostics/crop_advisor.py` | Порог, правила отображения и текст ответа |
| `backend/app/diagnostics/` | Прочий анализ фото, текста и правила вывода |
| `backend/app/knowledge/` | Подбор инструкций |
| `backend/app/storage/` | Таблицы и сессии SQLite |
| `backend/scripts/train_classifier.py` | Обучение и экспорт ONNX |
| `backend/scripts/activate_model.py` | Проверка кандидата и запись в реестр |
| `backend/data/knowledge/` | Справочные материалы |
| `backend/data/models/` | Реестр, веса, манифесты и отчёты моделей |
| `backend/data/datasets/` | Разметка, лицензии, разбиения и галереи |
| `.cache/datasets/` | Исходные фотографии; здесь есть единственные копии |
| `.cache/thumbnails/` | Уменьшенные копии для обучения; пересоздаются |
| `react-frontend/src/` | Интерфейс |
| `backend/agro_advisor.db` | Личная история, фотографии и база знаний |

Для початков начните с `backend/data/datasets/corn_ear_v2/review.html`
и `dataset_card.json`. `corn_ear_v2` — расширенная подборка; `corn_comparison_v1`
содержит зафиксированные эксперименты. Не смешивайте их train/test: снимки могут
повторяться.

## Размер и обслуживание

Большую часть места занимают оригиналы фотографий и Python с PyTorch.
`.venv` и `node_modules` содержат установленные зависимости.

```powershell
# Аудит; --apply удаляет только разрешённые копии и кэш.
python backend/scripts/optimize_storage.py
# Компактная копия без обучающих фотографий и PyTorch.
python backend/scripts/export_runtime.py
# Проверки сервера (из корня проекта).
python -m unittest discover -s backend/tests
```

Не удаляйте `.cache/datasets` целиком: часть оригиналов находится только там.

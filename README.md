# 🌽🌻 Agronom AI

Локальный прототип предварительной диагностики **кукурузы и подсолнечника** по фотографии.
Выберите культуру и часть растения, загрузите фото и при необходимости добавьте описание.
Для каждой культуры используется отдельный классификатор. Диагностика после установки работает без сети.

## Запуск

Нужны Python (проверено на 3.12), Node.js и npm. Команды из корня проекта:

```powershell
python -m pip install -r requirements.txt
npm.cmd ci --prefix react-frontend
npm.cmd run build --prefix react-frontend
python -m uvicorn main:app --app-dir backend --reload
```

Откройте http://127.0.0.1:8000. Для последующих запусков можно использовать `start.bat`.
Разработка интерфейса: `npm.cmd run dev --prefix react-frontend` при работающем Python-сервере.

## Классы и ограничения

| Культура | Метки набора |
| :--- | :--- |
| Кукуруза, лист | Blight (1 146), Common_Rust (1 306), Gray_Leaf_Spot (574), Healthy (1 162) |
| Подсолнечник | Downy mildew (120), Fresh Leaf (134), Gray mold (72), Leaf scars (140) |

`Leaf scars` означает повреждения листа без установленного возбудителя. Класс `Blight`
сохранён как обозначение набора без уточнения конкретного патогена.
В классе Gray mold присутствуют корзинки; отдельного класса здоровых корзинок нет.
Поэтому модель может опираться на вид органа и фон: классификация корзинок требует особенно
осторожной интерпретации и дополнительных отрицательных примеров перед практическим применением.

Приложение не определяет культуру автоматически и не имеет надёжного детектора посторонних объектов.
Выбор культуры должен соответствовать фото. Поддержка стеблей, целого растения и новых болезней
потребует дополнительных данных. Фаза развития сохраняется как контекст, но модель не обучена
на отдельных фазах. Текст используется для уточнения и проверки противоречий, а не для
придумывания диагноза без изображения.

Порог отображения гипотез — 65%. Процент является оценкой модели, а не подтверждённой вероятностью
болезни. После проверки пользовательских фотографий выдача вердикта «здоров» для новых культур
отключена: даже оценка Healthy 98–99% встречается на изображениях с видимыми поражениями.
Такой результат теперь означает «отсутствие заболевания не подтверждено», включая отображение
старых результатов истории (исходные записи в БД не изменяются). Это ограничение вывода,
а не дообучение или исправление распознавания неизвестных заболеваний.
В новых ответах пояснение сохраняет выбранный класс «Здоровый лист» и его оценку отдельно
от вывода об отсутствии заболевания. Записи, уже сохранённые как `insufficient_data` с нулевой
оценкой, автоматически не пересчитываются: исходный выбор модели в них не сохранялся.
Здоровый класс не исключает болезни, отсутствующие в наборе. При низкой уверенности,
плохом фото или недоступной модели приложение сообщает о недостатке данных.
Для новых культур пока выдаются общие шаги осмотра; база агрономических рекомендаций и факторов
развития болезней ещё не подготовлена. Картофельные статьи к новым культурам не применяются.

## Обучение и проверка

Используется замороженный ImageNet MobileNetV2 и отдельная обучаемая голова
StandardScaler + LogisticRegression для каждой культуры. Готовый backbone взят из существующего
модуля проекта; картофельная голова в диагностике новых культур не участвует.
Снимки группируются по perceptual hash, конфликтующие группы исключаются.
Обучение, валидация и тест разделены по группам; температура калибруется только на валидации.
Это снижает утечки похожих снимков, но не заменяет разделение по растениям и независимый полевой тест.

Результаты первоначального обучения (seed 42):

| Культура | Обучение / валидация / тест | Точность на тесте | Ответы с оценкой ≥65% | Верных среди них |
| :--- | :--- | :--- | :--- | :--- |
| Кукуруза | 2 508 / 837 / 837 | 93,5% (783/837) | 784/837 | 750/784 (95,7%) |
| Подсолнечник | 278 / 93 / 93 | 93,5% (87/93) | 90/93 | 86/90 (95,6%) |

Перед разделением исключены 6 конфликтующих похожих изображений кукурузы и 2 подсолнечника.
Эти результаты относятся к классификатору на данных набора, до дополнительных ограничений
интерфейса по качеству фото и выбранному органу. Они не являются полевой оценкой точности приложения.
Обучалась только линейная классифицирующая часть; признаки MobileNetV2 не дообучались.
Внутренняя выборка не проверяет другие заболевания, общий вид растений и новые условия съёмки.
Проверка API на заранее успешно распознанных примерах проверяет подключение модели, а не её обобщение.

Повторный аудит всех отложенных снимков без изменения весов:

```powershell
python backend/scripts/audit_crop_models.py
```

Отчёт сохраняется в `.cache/diagnosis_audit/holdout_audit.json`: сравнение с сохранёнными
предсказаниями, матрицы ошибок и число больных снимков, отнесённых к Healthy.
Для улучшения модели нужны размеченные независимые полевые снимки, расширение классов и
отдельная проверка неизвестных поражений. Пользовательские снимки не добавляются в обучение автоматически.

Архивы и распакованные изображения находятся отдельно по источникам в
`.cache/datasets/corn_expansion/`. Загрузка поддерживает продолжение; для TARI и Pretoria
проверяются опубликованные MD5, дополнительно сохраняются SHA256. У зеркала TOM2024 нет
опубликованной контрольной суммы в карточке загрузки: SHA256 фиксирует полученный файл,
но не доказывает совпадение с релизом Mendeley. Выборка Pretoria проверяется по CRC каждого
ZIP-файла и локальному SHA256; контрольная сумма всего большого архива для выборки не проверяется.

Аудит создаёт:

- [audit.json](backend/data/datasets/corn_expansion/audit.json) — количества, повторы, конфликты, недостатки покрытия.
- `.cache/datasets/corn_expansion/review/manifest.jsonl` — путь, источник, исходная и согласованная метки,
  размеры, хеши, группа похожих снимков, причина исключения.
- В той же папке `train_candidate.jsonl`, `validation_candidate.jsonl`, `external_review.jsonl`,
  `quarantine.jsonl` — предварительные списки. Изображения физически не удаляются.
- `.cache/datasets/corn_expansion/review/gallery.html` — локальная галерея примеров с переходом к оригиналам.
- [current_model_review.json](backend/data/datasets/corn_expansion/current_model_review.json) — проверка
  неизменённого классификатора на внешней выборке и четырёх пользовательских примерах.

Точные совпадения проверяются по файлу и декодированным пикселям, похожие — по pHash с расстоянием ≤6.
Совпадающие временные метки TOM2024 также связываются в одну группу; это консервативная подсказка
из имени файла, не подтверждённый идентификатор растения. В обучение допускается один представитель
группы. Конфликты меток, изображения меньше 96 пикселей по стороне, неоднозначные диагнозы и
пересечения с внешней проверкой отправляются в `quarantine`. Эти эвристики не находят все
обрезки/повороты и не заменяют экспертную проверку. Старые validation/test также не используются
как кандидаты для нового обучения, включая их найденные похожие копии.

`Blight`, `Helminthosporiose-D`, `Rouille-D`, `Striure-D` и `Virose-D` не переименовываются
автоматически в конкретные болезни. В Pretoria сохраняются все отметки CSV, включая `Other`
и `UnidentifiedDisease`. `NoFoliarSymptoms` означает отсутствие отмеченных симптомов на листьях,
а не доказанное здоровье растения. Все источники пока относятся к листьям: здоровых початков,
стеблей и корней в этот сбор не добавлено. Южный гельминтоспориоз и пузырчатая головня остаются
пробелами покрытия до фактического получения и проверки соответствующих изображений.

80 снимков Pretoria выбраны с выравниванием групп диагнозов для первоначального аудита.
Они не отражают частоту болезней в поле. Метрики текущей модели считаются отдельно для
однозначно сопоставимых одиночных меток; неизвестные ей болезни и смешанные случаи сохранены
в подробном отчёте. Пользовательские метки не проверены независимым экспертом и в метрики Pretoria
не включены. После изменений источников повторите аудит, галерею и проверку модели.

При визуальной проверке нескольких примеров TARI у класса летального некроза повторялся
зелёный фон, у других классов часто светлый. Это возможная подсказка для модели, не связанная
с болезнью; необходима проверка на другом источнике. Результаты просмотра сохранены в
[visual_review.json](backend/data/datasets/corn_expansion/visual_review.json). Все метки
датасетов пока считаются авторскими аннотациями, а не независимо подтверждёнными диагнозами.

Результат первого аудита (21 октября 2026): 3 918 новых изображений; вместе с исходным
набором и четырьмя пользовательскими примерами проверено 8 110 файлов. Найдены 70 изображений
меньше минимального размера и 27 групп похожих/связанных кадров с разными метками. Между
источниками совпадений выбранными эвристиками не найдено, что не доказывает их отсутствие.
Предварительные списки: 2 077 train, 503 validation, 84 external review; остальные 5 446
оставлены отдельно, в том числе старые validation/test и неоднозначные метки. В списках
кандидатов семь классов; отдельный northern_leaf_blight содержит 65 train и 20 validation.
Эти списки были результатом подготовки данных; последующий запуск обучения описан ниже.

### Переобученный кандидат кукурузы — не подключён

На подготовленных списках обучен кандидат
[expanded_v1](backend/data/models/corn_candidates/expanded_v1/manifest.json),
[отчёт обучения](backend/data/models/corn_candidates/expanded_v1/training_report.json),
[решение по результатам проверки](backend/data/models/corn_candidates/expanded_v1/review_decision.json).
Действующей остаётся исходная четырёхклассовая модель; кандидат не прошёл проверку качества.

Обучено семь классов на 2 077 исходных изображениях; для каждого использованы оригинал и две
детерминированные аугментации (обрезка, отражение, поворот, яркость). Вклад классов и источников
внутри класса уравновешен весами. На 503 исходных валидационных изображениях выбраны C из
{0.01, 0.1, 1} по macro-F1 и температура по log-loss. Выбраны C=1 и температура 2.133.
Валидационное совпадение с разметкой — 97,4%; это не полевая оценка. MobileNetV2 оставалась
замороженной: переобучался классификатор LogisticRegression, полного fine-tuning нейросети не было.
Внешние фотографии не использовались для обучения, подбора C или температуры.

| Проверка на одних и тех же снимках Pretoria | Исходная модель | Кандидат |
| :--- | :--- | :--- |
| Три сопоставимых класса, 24 фото | 6 совпадений | 11 совпадений |
| Среди ответов с оценкой ≥65% | 3 из 15 | 6 из 13 |
| Северный гельминтоспориоз, 8 одиночных примеров | Отдельного класса нет | 1 совпадение |
| Healthy с оценкой ≥65% на 72 снимках без метки здорового листа | 0 | 5 |

На всех 32 внешних изображениях с поддерживаемой одиночной меткой кандидат совпал с разметкой
в 12 случаях. На четырёх пользовательских снимках он выбрал соответственно Healthy (77,3%),
курвуляриозную пятнистость (82,8%), серую пятнистость (97,0%) и Healthy (96,6%). Отсутствующие
болезни не появились от увеличения числа классов, а северный гельминтоспориоз по-прежнему
плохо переносится на другой источник. Поэтому улучшение на части снимков недостаточно для активации.
Это сырые ответы модели: политика приложения по-прежнему не выдаёт подтверждение здоровья.

Веса, исходные метки и вероятности сохранены в
[external_review.json](backend/data/models/corn_candidates/expanded_v1/external_review.json).
Резервная копия прежней модели находится в `.cache/models/corn_legacy_20261021`.
Исходные validation/test зафиксированы в
[legacy_holdout.json](backend/data/datasets/corn_expansion/legacy_holdout.json), поэтому аудит не
переопределяет их при смене активной модели. Признаки кэшируются в `.cache/features/corn_expanded/`.

После регистрации пользователя в Opera GX повторный запрос Mendeley из скрипта всё ещё вернул
HTTP 403. Сессия браузера не подключена к инструментам проекта. Для ручной загрузки нужен
`Download All` набора https://data.mendeley.com/datasets/sb4wwjs8bz/1; архив следует сохранить в
`.cache/datasets/corn_expansion/mendeley_bangladesh/incoming/`. На момент обучения файлов там
не было. Новый архив сначала требует проверки содержимого, меток и пересечений с тестовыми
изображениями; он не добавляется к обучению автоматически.

Исходный классификатор на 24 снимках Pretoria с сопоставимой одиночной меткой
(здоровый лист, обыкновенная ржавчина, серая пятнистость) совпал с разметкой в 6 случаях.
Из 15 ответов с оценкой ≥65% совпали 3. Эти числа относятся только к небольшой
стратифицированной выборке и сырому классификатору, до ограничений вывода приложения.
Четыре пользовательских примера проверены отдельно и в эти числа не включены.

### Код приложения

- `backend/app/crops.py` — реестр культур, метки датасетов и отображаемые названия.
- `backend/app/diagnostics/crop_model.py` — локальная загрузка и запуск моделей с проверкой хешей.
- `backend/app/diagnostics/crop_advisor.py` — ограничения входа и формирование предварительного ответа.
- `backend/main.py` — диагностика, сохранение и фильтрация истории по культуре.
- `react-frontend/src/crops.js` — выбор культуры, фаз и частей растения.
- `backend/scripts/prepare_crop_datasets.py` — загрузка и установка данных.
- `backend/scripts/train_crop_models.py` — обучение моделей активных культур.

`GET /api/history` показывает активные культуры; `?crop=Кукуруза` или `?crop=Подсолнечник`
фильтрует историю на сервере. `GET /api/knowledge?crop=...` возвращает метки набора,
не выдавая их за полноценный справочник лечения.

## Бэклог: картофель

Картофель исключён из основного интерфейса; дальнейшее обучение и развитие отложены.
Старые модели, код, база знаний и история сохранены. API принимает явное `crop: "Картофель"`
для совместимости со старыми клиентами; по умолчанию теперь выбирается кукуруза.
Архив описания прежнего прототипа: [LEGACY_PROJECT.txt](backend/data/models/potato/LEGACY_PROJECT.txt).

## Происхождение данных

У кукурузы Kaggle указывает `Data files © Original Authors` и происхождение из PlantVillage/PlantDoc.
У подсолнечника Kaggle указывает `Unknown` и ссылку на исходный Mendeley-набор
https://data.mendeley.com/datasets/b83hmrzth8/1. Эти значения сохранены без предположений о лицензии.
Перед распространением данных и моделей необходимо уточнить условия исходных наборов.
Сведения и лицензия MobileNetV2 сохранены рядом с каждой моделью.
